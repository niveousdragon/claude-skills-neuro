# Инструкции для Клода

> ## ⛔ АГЕНТ — ПРОЧТИ ЭТОТ ФАЙЛ ЦЕЛИКОМ, ПРЕЖДЕ ЧЕМ ЧТО-ЛИБО ДЕЛАТЬ
>
> Как только ты **склонировал, открыл или увидел** этот репозиторий — сначала
> прочитай весь этот файл, и только потом действуй.
>
> Когда пользователь просит «поставь скиллы» (в любой формулировке), это значит
> **ПОЛНУЮ установку**: кастомные скиллы из `skills/` **И** плагины из marketplace.
> Это **Шаги A + B + C** ниже — все три.
>
> **Частая ошибка:** скопировать только папки из `skills/` и остановиться. Так
> ставится меньше половины набора. Задача НЕ выполнена, пока не пройдены Шаг A,
> Шаг B и проверка (Шаг C). Не объявляй готовность раньше.

Этот репозиторий раздаёт скиллы коллеге-нейробиологу. Цель — чтобы пользователь
одним запросом получил **весь набор**, а не только два кастомных скилла.

Пользователь, скорее всего, неопытен в CLI: не заставляй его копировать команды
вручную больше необходимого, делай шаги сам и объясняй простыми словами.

## 1. Полная установка при первом использовании

Предупреди пользователя одной фразой, что поставишь весь набор (это подтянет
файлы из интернета и добавит команды), и, если он не против, ставь всё подряд:
сначала Шаг A, затем Шаг B, затем проверка (Шаг C).

### Шаг A. Кастомные скиллы из репозитория

В `skills/` лежат `deep-analysis`, `figure-alignment`, `figure-audit`, `tex-to-docx`, `share-figure`,
`auditing-structural-debt`, `lossless-doc-compress`, `bibliography-lockfile`,
`msu-publication-clearance`, `meeting-memo` и `avoid-ai-writing`. Их нужно
скопировать в `~/.claude/skills/` (по папке на скилл). Копируй папку целиком:
у скилла могут быть вспомогательные файлы рядом с `SKILL.md` (например, у
`tex-to-docx` — скрипт-конвертер). Способ — на твой выбор:

- **Скриптом** (если можешь запускать скрипты в этом окружении):
  - Windows (PowerShell): `powershell -ExecutionPolicy Bypass -File <путь к репозиторию>\install.ps1`
  - macOS / Linux: `bash <путь к репозиторию>/install.sh`
  - (`-ExecutionPolicy Bypass` нужен, потому что у пользователя может быть запрещён
    запуск скриптов по умолчанию.)
- **Вручную** (надёжнее, если запуск чужого скрипта отклоняется): просто скопируй
  каждую папку из `skills/<имя>` в `~/.claude/skills/<имя>` своими файловыми
  инструментами. Результат тот же — это всего лишь копирование папок.

Проверка Шага A: в `~/.claude/skills/` появились папки `deep-analysis/`,
`figure-alignment/`, `figure-audit/`, `tex-to-docx/`, `share-figure/`, `auditing-structural-debt/`,
`lossless-doc-compress/`, `bibliography-lockfile/`, `msu-publication-clearance/`,
`meeting-memo/` и `avoid-ai-writing/`, в каждой есть `SKILL.md` (в `tex-to-docx/` рядом с ним — `tex2docx.py`,
в `msu-publication-clearance/` — `fill_clearance.py`,
в `meeting-memo/` — `transcribe.py`,
в `figure-audit/` — `figaudit.py` и `LICENSE-OpenResearch`,
в `auditing-structural-debt/` — ещё четыре файла, в `lossless-doc-compress/` —
подпапка `references/` с пятью файлами, в `bibliography-lockfile/` — ещё четыре
файла: генератор, хук и шаблоны, в `avoid-ai-writing/` — `ORIGIN.md` и `LICENSE`;
копируй папку целиком).

> `lossless-doc-compress` и `avoid-ai-writing` — единственные скиллы в `skills/`,
> написанные не нами: это снимки сторонних скиллов под MIT (см. `ORIGIN.md` в папке
> каждого). Правки в них не вносим — при обновлении папка перезаписывается копией
> из upstream.

**Внешняя зависимость (только для `tex-to-docx`).** Этому скиллу нужен `pandoc` —
без него он не работает вообще. Проверь `pandoc --version`; если его нет, скажи
пользователю поставить (`winget install --id JohnMacFarlane.Pandoc` на Windows,
`brew install pandoc` на macOS) и заодно выполни `pip install pymupdf` — он нужен,
чтобы векторные картинки (PDF/EPS) не оказались в Word пустыми рамками. Остальные
скиллы ничего ставить в систему не требуют, так что на этом шаге не блокируйся:
если пользователь не собирается конвертировать LaTeX в Word, отложи и иди дальше.

**Внешняя зависимость (только для `figure-audit`).** Проверке рисунка из скрипта нужен
лишь matplotlib, который у пользователя уже стоит, раз он строит рисунки. Проверке
готового PDF (рисунок из Prism, Illustrator, R) нужен тот же `pymupdf`, что и для
`tex-to-docx`. Ставить отдельно ничего не нужно, и на этом шаге не блокируйся.

**Внешняя зависимость (только для `msu-publication-clearance`).** Скрипту заполнения
бланка нужен `python-docx` (`pip install python-docx`). Проверку «бланк уместился на одну
страницу» он делает через установленный MS Word (на Windows нужен ещё `pywin32`, в
Anaconda он уже есть); без Word скрипт заполняет бланк и прямо пишет, что число страниц
не проверено. Не блокируйся: ставь, только если пользователь оформляет заключения.

**Внешняя зависимость (только для `meeting-memo`).** Расшифровке записи нужен
`faster-whisper` (`pip install faster-whisper`); при первом запуске он скачает модель
распознавания (около 1,6 ГБ). Звук из `.webm`/`.mp4` он читает сам, `ffmpeg` не нужен.
Если у встречи уже есть готовая расшифровка (Телемост её сохраняет), скилл работает
и без него. Не блокируйся: ставь, когда пользователь впервые принесёт запись.

**Внешняя зависимость (только для `auditing-structural-debt`).** Скрипту переписи
`census.sh` нужны git и POSIX-оболочка: на Windows это Git Bash, он ставится вместе
с Git. Отдельно ставить нечего, и на этом шаге тоже не блокируйся — без оболочки
скилл работает, просто его измерения выполняются по одному вручную.

### Шаг B. Плагины (через marketplace)

Это остальная часть набора. Команды `/plugin` — встроенные команды сессии Claude
Code. **Ты, скорее всего, не можешь выполнить их сам** (нет такого инструмента) —
тогда их вводит пользователь.

**Как правильно отдать их пользователю (важно — здесь легко ошибиться):**

- Дай команды **по одной на строку**, и попроси вводить их **по одной за раз**:
  вставил строку → Enter → следующая.
- Предупреди: **каждая строка должна начинаться ровно с `/` (символ `/` — первый,
  без пробела перед ним)**. Пробел в начале превращает команду в обычный текст, и
  она не выполнится. Это самая частая причина «не сработало».
- Несколько команд в одну строку через пробел **не работают** — только по одной.

Команды (полный набор):

```text
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

/plugin marketplace add Imbad0202/academic-research-skills
/plugin install academic-research-skills@academic-research-skills

/plugin install skill-creator@claude-plugins-official
```

**Почему именно так (не упрощай имена!):**

- `superpowers@superpowers-marketplace` — указывай **полное имя с marketplace**.
  Если написать просто `superpowers`, автодополнение легко соскальзывает на
  похожий `superpowers-chrome` (это браузерный инструмент, не тот плагин). Нам
  нужен именно `superpowers` — основная библиотека (TDD, debugging, планы и т.д.).
- `skill-creator@claude-plugins-official` — `skill-creator` лежит в **официальном
  встроенном** marketplace `claude-plugins-official` (он уже подключён по
  умолчанию, отдельный `marketplace add` не нужен). Без суффикса `@…` имя может не
  разрешиться.

После установки каждого плагина CLI пишет «Run /reload-plugins to apply» — попроси
пользователя в конце один раз выполнить `/reload-plugins`. Если плагины не
появятся в списке — пусть перезапустит сессию Claude Code.

> `academic-research-skills` приносит команды `/ars-*` и скилл `deep-research` —
> отдельно ставить ресёрч не нужно. Лицензия ARS — CC BY-NC 4.0, для академической
> работы подходит.

## 2. Что когда вызывать (после установки)

### Кастомные скиллы
- **`deep-analysis`** — расследовать баг, профилировать медленный код, сравнить
  алгоритмы, разобрать аномалию в результате. Работает в изолированной папке,
  основной код не трогает, в конце даёт handoff-резюме.
- **`figure-alignment`** — создание/правка мультипанельных matplotlib-фигур для
  публикаций: панели не выравниваются, нужен квадрат, правка одной панели ломает
  другие, общий GridSpec, программная проверка выравнивания.
- **`figure-audit`** — подготовить рисунок к подаче в журнал или проверить готовый:
  ширина под колонку (одна, полторы, две), размер шрифта в печати, встроены ли шрифты
  (не Type 3), какой формат и dpi принимает журнал, налезающий и обрезанный текст,
  правила конкретного журнала. Требования Nature (и Nature Neuroscience), Cell Press, eNeuro, PLOS и eLife
  записаны в таблицу скрипта `figaudit.py` с адресом страницы и датой проверки; журнала
  нет в таблице — агент читает его страницу, а не вспоминает. Проверку по заготовке
  взяли из OpenResearch (alphaXiv, MIT), см. `skills/figure-audit/LICENSE-OpenResearch`.
  Проверяет и готовый файл, сделанный не в Python: PDF из Prism или Illustrator и
  заголовок TIFF (размер, dpi, сжатие, объём файла).
- **`tex-to-docx`** — перевести `.tex`-статью в Word для соавтора, редактора или
  журнала: картинки (включая векторные PDF/EPS), формулы, таблицы, цитаты и
  кросс-ссылки сохраняются, а комментарии и черновые пометки в файл не попадают.
  Нужен `pandoc`; конвертер лежит рядом со `SKILL.md`.
- **`share-figure`** — собрать фигуру для отправки коллеге/рецензенту так, чтобы её
  можно было воспроизвести: картинка + генерирующий код + ровно нужные данные +
  provenance; «готово» = чистая копия бандла воспроизводит фигуру, а не «скрипт
  запустился».
- **`auditing-structural-debt`** — разобрать **весь** проект на накопленную сложность:
  что дублируется, какие модули разрослись, что уже никто не вызывает, где документация
  описывает несуществующее. Это не ревью отдельной правки, а вопрос «во что обошлось
  накопление правильных правок». Только диагноз, код не трогает. Итог — реестр
  `docs/architecture-debt.md`: у каждой находки постоянный номер, цена и оценка
  «а если не чинить», и следующий прогон его продолжает, а не переписывает. Уместен
  перед крупным релизом, перед тем как код унаследует другой человек, и перед выкладкой
  кода вместе со статьёй. Прогон долгий и дорогой — предупреди пользователя заранее.
- **`lossless-doc-compress`** — сжать текст (design doc, план, README, черновик раздела,
  LLM-набросок), не потеряв ни одного факта: вырезается только доказуемый мусор — вода,
  хеджирование, LLM-слоп, повторы. Всё спорное не режется, а помечается флагом для автора;
  числа, решения, оговорки, таблицы и код неприкосновенны. На выходе три вещи: сжатый
  документ, лог вырезок по категориям и короткий scorecard. Это **не** суммаризация и
  **не** абстракт — там потеря информации допустима, здесь запрещена; для этого скилл не
  зови. Скилл сторонний (MIT), см. `skills/lossless-doc-compress/ORIGIN.md`; внутри он
  ссылается на братские скиллы `ml-system-design-review` и `ai-stage-gate` — их у нас нет,
  и ставить их не нужно.
- **`bibliography-lockfile`** — навести порядок со списком литературы: `.bib` не
  пишется руками, а генерируется из издательских баз (Crossref, arXiv, PMLR,
  OpenAlex) по реестру идентификаторов `sources.yaml` — имя автора не проходит через
  память человека или модели. Зови, когда в проекте цитируют статьи в BibTeX и записи
  добавляют вручную, когда разворачивают библиографию для новой статьи и когда
  проверщик ссылок нашёл выдуманные ссылки или неверных авторов.
- **`msu-publication-clearance`** — оформить экспертное заключение о возможности
  открытого опубликования (МГУ, биофак) на статью, тезисы, материалы сборника,
  диссертацию и автореферат. Скрипт `fill_clearance.py` меняет в бланке только текст,
  выделенный жёлтым, снимает выделение и проверяет, что бланк уместился на одну
  страницу. Сам бланк в репозитории не лежит: он меняется, и его каждый раз берут
  свежим с сайта факультета. Скилл заранее напоминает, что заключение нужно до подачи
  в журнал, препринта и доклада, и перечисляет, что нести вместе с бланком (постер,
  письмо организации соавтора и т.д.).
- **`meeting-memo`** — из записи встречи (Телемост, Zoom, диктофон) или её сырой
  расшифровки сделать мемо, по которому можно действовать: решения, сроки с днём
  недели, позиции участников, поручения «кто / что / когда», открытые вопросы. У каждого
  утверждения таймкод, чтобы спорное место можно было найти в записи за минуту;
  неразборчивые места и восстановленные имена вынесены в отдельный список для проверки.
  Если расшифровки нет, делает её сам скриптом `transcribe.py` (нужен `faster-whisper`);
  на обычном компьютере это занимает в 1–1,5 раза больше времени, чем шла встреча.
- **`avoid-ai-writing`** — вычистить из текста приметы машинного письма: частокол тире,
  злоупотребление жирным, «правило трёх», конструкцию «не X, а Y», шаблонные концовки,
  разговорные хвосты вроде «надеюсь, это поможет», расплывчатые ссылки на «экспертов».
  Три режима: `detect` (только пометить), `rewrite` (переписать, по умолчанию) и `edit`
  (править файл на месте). Есть профили голоса и контекста (`technical-blog`, `docs`
  и др.) и три уровня серьёзности находок. Ключевое ограничение, ради которого скилл сам
  же и написан осторожно: это редакторский инструмент, **не** вердикт об авторстве —
  у детекторов доля ложных срабатываний на неносителях английского превышает 60 %.
  Второе ограничение наше: словарные таблицы там английские, на русском тексте работают
  только структурные правила, а потолок «1 тире на 1000 слов» к русскому неприменим
  напрямую (у нас тире обязательно на месте опущенной связки). Подробнее — в
  `skills/avoid-ai-writing/ORIGIN.md`. Скилл сторонний (MIT).

### Из `superpowers`
- `brainstorming` — перед новой разработкой, разложить замысел до кода.
- `systematic-debugging` — любой баг/непонятное поведение.
- `test-driven-development` — пишется фича.
- `writing-plans` / `executing-plans` — многошаговая работа с чекпойнтами.
- `verification-before-completion` — пользователь объявляет «готово» без проверки.

### Из `academic-research-skills`
- `/ars-plan` — структура статьи по главам.
- `/ars-lit-review` — обзор литературы.
- `/ars-citation-check` — проверка цитат на галлюцинации.
- `/ars-reviewer` — симуляция рецензии.
- `/ars-format-convert` — конвертация LaTeX / DOCX / PDF / Markdown.
- `deep-research` — основательный обзор темы с проверяемыми источниками.

Если задача подходит — вызывай нужное сам, не жди, что пользователь назовёт скилл.

## 3. Как создать новый скилл (если попросят)

Пользователь, скорее всего, не пользуется терминалом и git — **бери всю механику
на себя**. Не проси его создавать файлы или коммитить вручную. Алгоритм:

1. Выясни у пользователя своими словами две вещи: **когда** приём нужен (триггеры,
   ситуации, формулировки) и **как** делать правильно (шаги). Задавай вопросы,
   если чего-то не хватает.
2. Сам создай файл `~/.claude/skills/<имя>/SKILL.md` по шаблону ниже.
3. Проверь, что скилл подхватился, и кратко объясни пользователю, как его звать.
4. Если пользователь хочет поделиться с лабораторией — скопируй папку скилла в
   `skills/` этого репозитория и сделай коммит сам (`git add` + `git commit`).
   Сообщи, что остальным он станет доступен после обновления репозитория.

Шаблон `SKILL.md`:
```markdown
---
name: имя-через-дефис
description: Use when <конкретные триггеры и симптомы, когда применять>.
---

# Название

## Overview
Что это и главный принцип в 1–2 предложениях.

## When to Use
- симптом / ситуация 1
- симптом / ситуация 2

## Workflow
Пошагово, как делать правильно.
```
Ключевое — `description`: от третьего лица, начинается с «Use when…», перечисляет
конкретные триггеры (по нему скилл и находится).

Для серьёзного процесса (с тестированием скилла на субагентах) вызови
`writing-skills` из `superpowers`, либо мастер `skill-creator`.

---

## Чего НЕ делать

- Не копировать сторонние плагины (superpowers, ARS, skill-creator) в этот
  репозиторий — только ставить из marketplace. Исключение — одиночный скилл
  `lossless-doc-compress` и `avoid-ai-writing`: они лежат в `skills/` осознанно, снимками
  под MIT, потому что marketplace для них нет. Не удаляй их как «чужое» и не правь их
  файлы вручную — обновление делается перезаписью папки из upstream (адрес в `ORIGIN.md`).
- Не ставить `superpowers-chrome` вместо `superpowers` — это разные плагины (см.
  Шаг B). Если поставил по ошибке, удали: `/plugin uninstall superpowers-chrome@superpowers-marketplace`.
- Не редактировать рабочий код пользователя в рамках установки — твоя задача здесь
  только поставить набор скиллов и плагинов.
- Не останавливаться на Шаге A. Установка без плагинов (Шаг B) — это половина
  набора, а не готовый результат.
